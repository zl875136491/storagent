# ADR-001 虚拟存储一致性与边界

## 背景

旧稿把配额写成新的 Etcd 前缀，并把租约过期当成可以释放额度。对照现有代码后，这些假设不成立。

## 决定

1. 配额权威是 Mongo 双层事务账本（账号 + 租户）。虚拟存储不写 Etcd 配额，也不把专用 MinIO 池登记进旧 `minio_server`。
2. 软删除把 `used` 转到 `trashed`，两者都计入占用。只有确认物理清除后的那一次事务释放 `trashed`。
3. 对账扫描 `initializing`、`uploading`、`completing`、`aborting`、`reconciling` 以及 `active`、`soft_deleted`、`purge_pending`。计数低于实体合计时只向上补记，不因为租约过期把额度放掉。
4. MinIO 初始化或完成超时视为结果不明：保留预留，沿原上传会话查询；确认不存在后才在同一会话上重试，不新建第二条会话或目录。
5. 数据库租约 fencing 不能取消已经发出的 MinIO 请求。存在未结束的 `vs_minio_calls` 时，接管方不得清理或释放额度。
6. 管理凭据只用于账号治理，租户 Key 只用于数据面。交付窗口内，同一主体、同一幂等键、同一参数返回同一把 Key；窗口外和普通查询不返回明文。Key 有效期长于交付窗口。
7. 注销完成（`retired`）后，外部租户 ID 可以用新的 `tenant_id` 和新的 generation 重新进入。逻辑名在清除确认后释放，不再被历史记录永久占用。
8. `cancel-retire` 只在 `purge_started=false` 且没有 `purge_pending` 对象时成功，租户回到 `frozen`。
9. `complete` 使用服务端 `list_parts` 的分片号和 ETag。请求体里的 ETag 不参与完成。
10. 即使 broker 在同一台 Mongo 上，也使用独立库 `storagent_vs_broker` 和独立账号，队列名是 `storagent-vs.<region>.v1`。
11. 现有代码只有 OA springboard 和本系统口令登录，测试环境没有 OIDC issuer。控制台先用管理凭据，不把 OIDC 当成已经存在的能力。

## 部署边界

共享的 10.32.12.110:27017 是单机 MongoDB 6.0.20，不能做多文档事务，也不能改成副本集。测试范围新增独立副本集和只监听本机的 MinIO 池。旧 Storagent 容器保持停止，不重置它们的卷。
